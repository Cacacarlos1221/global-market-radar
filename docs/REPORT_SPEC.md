# Global Market Radar · 每日 HTML 晨报内容与版式规范

> **状态：当前采用的 V1 报告产品规范（2026-11-03 冻结）**
>
> 本文件定义**用户每天看到什么、为什么这样排列、每块信息来自哪里，以及怎样验收**。它是未来独立 Agent Harness 和 HTML 模板升级的共同产品契约。字段详细定义以 [DATA_DICTIONARY.md](DATA_DICTIONARY.md) 为准，现有实际渲染实现以 [scripts/render.py](../scripts/render.py) 为准。

## 1. 目标和阅读顺序

面向 **北京时间 09:30 A 股开盘前**的个人市场研究，优先回答：

1. **发生了哪些价格变化？** 美元兑人民币、澳元汇率、美股三大指数及宏观指标，注明可比时点。
2. **市场为什么变化？** 已发生的市场表现、可能原因与不确定性。
3. **世界上发生了什么重要事件？** 经过筛选和核实的新闻摘要。
4. **这些事件可能怎样影响今天的 A 股？** 提前提出可验证、条件性的判断。
5. **证据在哪？** 能跳转到引用报道，完整新闻线索不丢弃。

**固定信息架构：01 → 02 → 03 → 04 → 05 → 06 → 页脚数据状态。**

关键原则：**行情事实、新闻报道、推断分析、盘前预测分层呈现**。同一新闻与行情在时间上接近，不等于已经证明是行情的原因。

## 2. 每日 HTML 整体信息架构

```text
Global Market Radar / 全球市场晨报 · YYYY-MM-DD
报告日期（北京时间） | 实际数据采集时间（UTC） | 历史归档入口
│
├── 01 / 关键市场数据            [最先看：6张核心行情卡片]
├── 02 / 全量监测指标            [需要时细看：资产明细表]
├── 03 / 昨夜市场走势与原因      [价格驱动解释，不复述新闻清单]
├── 04 / 国际重要新闻综述        [核心脉络 + 3–5项重要事件]
├── 05 / A股开盘前研判           [条件性市场判断 + 行业影响 + 风险]
├── 06 / 新闻来源与参考资料      [引用文献 + 折叠的全部原始RSS]
└── 页脚：数据状态 + 不构成投资建议
```

### 01 / 关键市场数据

**形式**：响应式卡片，先显示关键资产，不在首屏放一长段文章。

| 展示对象 | 数据键 | 展示内容 |
| --- | --- | --- |
| **美元兑人民币（首位）** | `USD_CNY` | 1 USD 对多少 CNY；最新汇率、相对前一可用日线参考价变化、观察时点与报价类型 |
| 澳元兑人民币 | `AUD_CNY` | 1 AUD 对多少 CNY；最新汇率、相对前一可用日线参考价的涨跌幅、市场日期、报价类型 |
| 纳斯达克综合指数 | `NASDAQ` | 最近可用交易日数值和相对前日变化 |
| 标普500指数 | `SP500` | 同上 |
| 道琼斯指数 | `DOW` | 同上 |
| **澳元兑美元（末位）** | `AUD_USD` | 1 AUD 对多少 USD；保留但调到最后一张核心卡片 |

**阅读规则**：先看价格和方向，再看日期/口径。不同市场的观察日期不一定相同；休市不能把旧报价说成“昨天收盘”；实时价格不能冒充最终收盘价。缺失值用“暂无数据”，**严禁 0/估计值/模型猜测值冒充价格**。

**当前实现**：6 张卡片按上表顺序排列；新增的美元兑人民币使用 Yahoo Finance 的 `CNY=X`（USD/CNY），不是人民币兑美元的倒数报价。历史快照不补造数据，因此 2026-11-03 等旧日报上的 USD/CNY 卡片会标记“暂无数据”，从下一次成功采集的新快照开始落入 JSON/CSV。卡片数值、日期与涨跌幅必须与原始 JSON 一致。未来若补充绝对涨跌额、银行买卖价等，先明确字段与来源，不能只改文案。

### 02 / 全量监测指标

**形式**：可横向滚动的详细表格，保留全量监控资产。

- 核心汇率与美股指数，以及美元指数、布伦特原油、黄金、美国 10 年期国债收益率、上证综指、沪深300等配置资产。
- 列：资产、最新值、相对参考日涨跌幅、行情日期、上游 UTC K 线时间、数据状态。
- 解释 `market_date` 与 `report_date` 的区别，特别注意**日线 K 线时间戳往往是 K 线开始时刻，不一定是收盘发生时刻**。
- 美债收益率等特殊单位必须按 `config/instruments.json` / 数据字典处理；相对百分比变化不等于基点变化。

这部分是为了核对、复用和后续分析，不需要替代 03 的解读。

### 03 / 昨夜市场走势与原因

**回答：**「价格发生了什么？可能由什么驱动？」

- 重点梳理最近一个已结束美股交易日三大指数变化及板块分化，并联系澳元、美元、利率、商品的同步变化。
- 对解释分层：**数据已证实** / **有外部依据的市场解释** / **待验证的推测**。
- 强调主要驱动和市场机制，不泛泛罗列 04 的每条新闻；不能声称已证明因果。
- 由 `data/analysis/...json` 的 `market_summary` 提供。
- 非美股交易日需注明休市及上次交易日的精确日期，转而突出最新宏观风险。

### 04 / 国际重要新闻综述（重点内容）

**回答：**「最近24小时有哪些真正重要的事件？为什么重要？」

**页面构成**：

1. **今日核心脉络**：开头 1 段自然语言综述，总结当日全球事件主线，避免与 03 逐句重复。
2. **精选重大事件卡片**：通常 **3–5 项**，最多 6 项，实际重大事件少时可以更少，不能为凑数量捏造。
3. 每张卡片固定包括：
   - **重要性**：例如 high / medium，按事件影响而非点击率决定；
   - **事件标题**：短而明确；
   - **事件事实**（`summary`）：已证实的信息、发生时间、涉及的机构/地区，必要时写明“据某媒体报道”；
   - **市场影响**（`market_impact`）：可能传导至哪些资产及行业，解释条件和不确定性；
   - **参考来源**（`source_ids`）：如 `[S1] [S2]`，点击可跳转到第 06 节。

**筛选逻辑**：相关性 × 新颖性 × 潜在市场影响 × 来源可靠性；对同一事件多篇文章进行合并、去重；优先央行、重要经济数据、美国科技业重大变化、地缘政治与能源、对中国权益市场有影响的政策。

**硬约束**：RSS 标题只作为候选线索；需要核实对应可靠报道或原始公告，才能写成事实。没有证据时必须注明无法确认或者不选入。**禁止将未经核实的原始标题自动生成“确定性新闻结论”。**

### 05 / 今日 A 股盘前研判

**回答：**「考虑已知国际信息，对尚未开盘的 A 股有哪些潜在影响？」

按下列顺序组织：

1. **整体倾向**：例如 `positive` / `negative` / `mixed` / `watch`，避免绝对化买卖结论；
2. **主要逻辑**：结合 01–04 已知数据与事件，形成条件性的盘前推演；
3. **行业影响**：半导体/AI、稀土/有色、能源、新能源、出口、金融等根据事件重要性灵活取舍，指出偏积极/偏消极/观望及原因；
4. **风险和观察点**：关键政治经济日程、汇率阈值、油价、美国股指期货、国内流动性等，不能凭空给准确点位。

**特别重要**：

- A 股开盘前写出的判断才可作为“盘前预测”。若已经开盘或盘后才生成，必须显式标记为盘中/盘后观察，**不得放进盘前胜率评估**。
- 因国内事件、政策与资金面可能更重要，不能直接把“纳指跌 → A股一定跌”写成结论。
- 数据字段：`a_share_bias`、`a_share_outlook`、`a_share_sectors[]`、`risks[]`、`uncertainty`。

### 06 / 新闻来源与参考资料

**形式**：分析引用在前，所有原始新闻候选线索在后（默认折叠）。

- **第一部分：实际被分析引用的来源**。展示 `[S1]`、标题、机构/媒体、发布时间、核验状态、可点击 HTTPS 链接。04 中的编号可跳转至对应来源。
- **第二部分：原始 RSS 线索**。默认折叠，点击“展开全部原始 RSS 新闻线索”后展示所有收集的标题、来源、时间及链接。要标记“未经独立核验”，不能混入正式证据。
- 早期 `evidence_urls` 仍兼容展示为“历史分析参考资料”，不删除历史引用。

**不再有独立的「06 数据质量」章节**。它移到页脚，但底层 JSON 中的数据质量/错误字段全部保留。

### 页脚 / 数据状态

一行简洁说明：**行情可用数/总数、RSS 线索数量、采集 UTC 时间、数据异常查看入口或提示**，以及不构成投资建议的声明。

系统发生缺失或异常时，前文相关区域也需要清楚提醒；**缩小数据质量在 UI 中的占比，不是取消质量监控**。

## 3. 三个分析章节如何避免重复

| 区域 | 核心问题 | 视角 | 不应该做的事 |
| --- | --- | --- | --- |
| 03 市场走势与原因 | 为什么涨跌？ | **资产价格与风险偏好** | 只把 RSS 新闻标题复制过来 |
| 04 国际新闻综述 | 发生什么重要事？ | **事件事实与传导机制** | 把时间重合推断成确定因果 |
| 05 A 股盘前研判 | 对下一市场时段意味着什么？ | **前瞻情景与行业影响** | 把盘后信息写进盘前预测 |

顺序不能颠倒：**先事实、再解释、再展望、最后追溯证据。**

## 4. 数据分层、字段映射和渲染职责

```text
Python 采集脚本
    └─ data/daily/YYYY/MM/YYYY-MM-DD.json
       ├─ quotes[]                → 01 核心卡片、02 行情表
       ├─ news[]                  → 06 原始 RSS 折叠区
       └─ collected_at_utc 等    → 页眉与页脚质量信息

ChatGPT 定时维护任务（将来也可由独立 Agent Harness 替代）
    └─ data/analysis/YYYY/MM/YYYY-MM-DD.json
       ├─ market_summary         → 03
       ├─ news_digest.overview   → 04 核心脉络
       ├─ news_digest.items[]    → 04 事件卡片
       ├─ news_sources[]         → 06 关联来源
       ├─ evidence_urls[]        → 06 老格式兼容
       ├─ a_share_bias/outlook   → 05
       ├─ a_share_sectors[]      → 05 行业影响
       └─ risks/uncertainty      → 05 风险与不确定性

scripts/pipeline.py + scripts/render.py
    ├─ index.html                        → 最新完整页面
    ├─ reports/YYYY/MM/YYYY-MM-DD.html   → 历史日报
    └─ reports/archive.html              → 按日期导航
```

- **不要让 LLM 直接编辑最终 HTML**。应写**可校验的 JSON**，由确定性 Python 模板合成页面，便于重跑、回归测试和更换模型。
- 每条 `news_digest.items[]` 至少有 `title`、`summary`、`market_impact` 与可解析的 `source_ids`；引用需对应 `news_sources[].id`。现有 `validate_analysis` 会验证部分约束。
- 所有数值以事实快照为准，不得由模型创造或“补齐”；模型分析需注明 `generated_at_utc` 和信息截点。
- **原始快照 append-only**，不因新闻筛选或分析补充而覆盖；分析 JSON 与生成网页允许在 Git 提交历史中有版本化修订。
- 面向数据研究继续保留 `data/history/quotes.csv` 与 `data/history/events.csv`，后续可以加预测结果/实际收盘对照表，而不破坏现有报告字段。

## 5. 实际自动更新流程（保持现状）

| 计划时间（北京时间） | 执行者 | 对应输出 |
| --- | --- | --- |
| **08:15** | GitHub Actions `.github/workflows/daily.yml` → Python 数据采集 | 当日 `data/daily/`、`data/history/`，先生成**基础 HTML** |
| **08:30** | 已启用的独立 ChatGPT 晨报任务 | 向用户发送晨报消息（目前与仓库分析不是同一份产物） |
| **08:45** | 已启用的独立 ChatGPT 仓库维护任务 | 读取仓库事实快照、核验重要新闻、写入 `data/analysis/` |
| 分析 JSON 推送后 | GitHub Actions `push` → `--render-only` | 自动重生成 HTML、更新归档并提交 |
| 代码/HTML 更新后 | GitHub Pages | 展示最终日报（存在发布延迟） |

这些是**计划触发时间而非完成 SLA**，特别是 08:45 才开始分析，不能保证 09:00 前完整发布。

**重要现状**：08:30 聊天晨报和 08:45 仓库维护是两项并行任务；不是“GitHub 主动将文件推送给 ChatGPT”。未来自部署 Agent 时，可以统一为**一份采集快照 → 一份经过核验的分析 JSON → 网页和推送复用**，但**当前尚未部署这套独立 Agent Harness**，本规范不把规划视为已经实现的能力。

## 6. 降级与兼容行为

| 情况 | 页面表现 | 数据与自动化处理 |
| --- | --- | --- |
| 当天只有原始数据、没有分析 JSON | 03/05 标记待补充，04 标记“尚无经过核验的新闻综述” | 06 仍可折叠展示当日 RSS |
| 已有旧分析，没有 `news_digest` | 保留旧 `market_summary` 和 A 股判断，04 暂缺 | 旧 `evidence_urls` 继续展示 |
| 模型提供未经引用的 `news_digest.items` | **不发布该条新闻结论**；新格式引用校验失败时应阻止更新 | 记录错误、保留上一可用页面 |
| 行情或新闻源不可用 | 清楚展示“暂无数据”或缺失新闻，不能造数 | `status` / `source_errors` 记录异常 |
| 市场休市或非交易日 | 说明最近行情对应的交易日期 | 不用报告日代替市场交易日 |
| 盘中/盘后补写报告 | 标明是观察/复盘，而非盘前预测 | 不进入未来盘前预测效果评估 |

## 7. 每日验收标准

- [ ] 01 六个核心指标（USD/CNY 第一、AUD/USD 最后）：数值、币种/单位、涨跌幅、市场日期、状态与当日快照一致。
- [ ] 02 所有监测资产无遗漏，缺失值不会被写成 0，观察时间与交易日口径准确。
- [ ] 03 解释市场走势，有依据且没有将推断表述成已证明因果。
- [ ] 04 有核心脉络和合理数量的重要事件；每条有事实、市场影响与来源编号。若无核验结果，则明确待补充。
- [ ] 05 含整体倾向、相关行业与主要风险，严格区分盘前预测和盘中/盘后观察。
- [ ] 06 每条引用链接有效、编号可对应 04；原始 RSS 默认折叠但仍可浏览。
- [ ] 页脚显示采集状态、数量、时间；详细异常留在 JSON。
- [ ] `python -m unittest discover -s tests -v` 通过；`python -m scripts.pipeline --render-only` 可重渲染已有日报。
- [ ] 已发布 `index.html` 与对应 `reports/YYYY/MM/YYYY-MM-DD.html` 内容一致；GitHub Pages 部署成功。
- [ ] 原始日报快照不被静默覆盖，修改均有 Git 提交记录。

## 8. 后续 Agent 开发应遵循的契约（尚未实现）

将来如果以 OpenAI / DeepSeek / Qwen API 在服务器或 GitHub Actions 运行独立 Research Agent，建议保持：

1. **Input**：只读 `data/daily/` 与其他明确来源；先检查资料采集日期、市场日期和缺失情况。
2. **Research**：按实时来源检索、去重、核实正文/公告，给出可追溯引用。
3. **Reasoning**：分别生成 market_summary、news_digest、a_share_...，并控制盘前时间截点。
4. **Validation**：JSON schema、引用 ID、数值一致性、时间逻辑、异常降级。
5. **Output**：只写 `data/analysis/`，触发 Python 模板构建；**不直接替换固定 HTML**。
6. **Observability**：记录模型、Prompt 版本、生成时间、数据快照版本、token/费用、失败原因与后续复盘指标（待实现）。

变更报告章节、字段或引用规则时，应先更新本文档与 [DATA_DICTIONARY.md](DATA_DICTIONARY.md)，再改代码与测试。

## 2026-11-04 交易日期说明与数据源修正

- 报告日期为北京时间晨报日期，不要求每个国际资产的 market_date 相同。11月4日A股开盘前，美股使用美东11月3日收盘，黄金、美元指数等也可能采用各自交易所的11月3日行情，这是正常的。
- 同为A股指数，上证综指和沪深300的最新交易日期理论上应一致；若上游返回不同日期，应标记疑似滞后。缺少涨跌基准的指数不能静默显示为质量全绿。
- 2026-11-04快照的上证综指 Yahoo 值为2026-11-02的3638.03，而上交所官网公布2026-11-03收盘3608.10。采取独立有来源的 source_correction 记录覆盖**页面展示层**，原 data/daily JSON 保留不变。
- HTML 页眉明确展示基础行情版或完整分析版、分析生成北京时间，以及汇率、美股、A股各自的行情所属日期。

## 2026-11 总控发布门禁（按完整晨报验收）

当日公共 HTML 应当只在事实层和 AI 分析层都完成后发布；保留前一日完整网页优于展示当日空白的03–05章节。ChatGPT 定时任务负责检查、触发数据任务、生成分析并核查线上发布，GitHub负责数据采集、结构校验与确定性HTML构建。

“完成”至少要求本地 release_check 通过、同日报告HTML存在、完整分析时间可追溯，以及 GitHub Pages 的最新部署成功。用户可能看到浏览器缓存，因此应给出具体报告链接并核验页面日期。完整规范参见 [OPERATIONS.md](OPERATIONS.md)。

## A股倾向的色彩编码（2026-11-04）

05 节总体倾向与行业细分使用同一套彩色文字标签：\`positive\` 绿色（偏利好），\`negative\` 红色（偏利空），\`mixed\` 紫色（多空交织），\`watch\` 琥珀色（重点观察），\`neutral\` 灰色（中性）。标签同时显示**中文描述与英文原始值**，兼顾日常阅读与后续数据研究。

色彩规范以 [README](../README.md#报告术语与标签定义统一规范) 为准；**不在每日 HTML 中重复解释这些标签的定义**。既有 JSON 如 \`mixed\` / \`watch\` 等原值不改，渲染器决定外观。未识别取值以灰色“未分类”显示，不静默归入 neutral。未来若增加正式 \`confidence\`，必须先定义其数据校准含义，再决定是否展示。
